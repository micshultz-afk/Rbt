# ReplaceMultipleSpaces — надёжная замена множественных пробелов

PowerPoint VBA: любое число пробелов больше одного → один пробел в любом `TextRange`, с сохранением форматирования между Runs.

## Быстрый старт

```vba
Dim n As Long
n = CollapseMultiSpaces(shp.TextFrame.TextRange)   ' удалено лишних пробелов; -1 = ошибка

' или обёртка под существующий лог проекта:
ReplaceMultipleSpacesDashes rng, slideIndex, shp
```

Файлы:

| Файл | Назначение |
|---|---|
| `ReplaceMultipleSpaces.bas` | модуль |
| `test_collapse_spaces.py` | проверка строкового алгоритма |

Установка: `Alt+F11` → Import File → `ReplaceMultipleSpaces.bas`.  
Обёртка `ReplaceMultipleSpacesDashes` ожидает символы проекта: `bDebugMode`, `TraceStart`, `TraceEnd`, `LogLine`, `ElapsedSeconds`, `g_ChangedElements`. Ядро `CollapseMultiSpaces` от них не зависит.

## Что ломалось в исходнике

| Проблема | Эффект |
|---|---|
| `text = run.Text` один раз, в цикле не обновляется | `InStr(text, "  ")` остаётся истинным → до 100 пустых `Replace` даже после успеха |
| `cnt` общий на все Runs, лимит 100 | после 100 замен по фигуре остальные Runs не обрабатываются |
| обход `Rng.Runs` вперёд + мутация через `Replace` | коллекция Runs перестраивается, часть Runs пропускается |
| правка только внутри Run | `" " \| " "` на стыке двух Runs остаётся двойным пробелом |
| `g_ChangedElements` всегда +1 | ложная статистика, даже если пробелов не было |
| `On Error Resume Next` без выхода | сбои глотаются, трассировка врёт об успехе |
| закомментированный `Replace$` по строке | единственный быстрый путь был отключён |

## Как сделано надёжно

1. **Ранний выход** — нет `"  "` → сразу 0, без циклов.
2. **Один Run** — `CollapseSpacesString` + присвоение `Text` (формат Run однороден, это безопасно и быстро: каждый проход `Replace$` сжимает все пары сразу → O(log n) по длине серии).
3. **Несколько Runs** — схлопывание **внутри каждого Run с конца** (индексы не плывут), затем `TextRange.Replace` для стыков Runs.
4. **Страховка** — бинарное схлопывание `32→1 … 2→1` через COM, если после лимита стыков ещё остался мусор.
5. **Защита от вылетов** — `Nothing`, пустой текст, недоступные Runs, ошибка `Replace` → возврат `-1` / безопасный `Exit`, без зависаний (`guard` на всех циклах).
6. **Счётчик изменений** — `g_ChangedElements` только при `removed > 0`.

## Скорость

- типичный случай (0–1 двойной пробел): один `InStr` + один проход;
- длинная серия внутри Run: строковый `Replace$` в цикле, без COM на каждое вхождение;
- стыки Runs: обычно 0–несколько COM `Replace`;
- худший случай ограничен `MAX_BOUNDARY_PASSES` и длиной текста.

## Ограничения

- схлопывается обычный пробел `Chr(32)`; неразрывный `Chr(160)` и табы не трогаются;
- ядро работает с переданным `TextRange` (абзац, shape, selection — любой);
- обёртка с логом компилируется только в проекте, где есть символы трассировки.
